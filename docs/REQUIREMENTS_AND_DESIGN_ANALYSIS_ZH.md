# vcrunyue.com 生产就绪与完整体验优化——需求与设计分析

> 文档日期：2026-07-17
> 适用版本：`main@1d394cf` 及其后续本轮改动
> 决策方式：基于现有代码、文档、近期提交、运行基线与依赖安全报告推导推荐方案；不虚构站主尚未提供的个人内容。

## 1. 当前项目现状与问题

### 1.1 已具备的基础

- 技术栈为 Next.js 16 App Router、React 19、Tailwind CSS 4、Framer Motion，页面默认使用 Server Components。
- 首页 `/`、游戏归档 `/game`、`robots.txt`、`sitemap.xml` 和站点图标均已实现并可静态生成。
- 内容已集中在 `app/content/**`，展示规则集中在 `presentation.js`，内容、资源、结构三类验证脚本均已建立。
- 博客、游戏、社交链接、SEO 图片和基础统计桥接已有可运行实现。
- 现有 `npm run check:content`、`check:assets`、`check:structure` 全部通过；放行字体下载网络后 `npm run build` 通过。
- 当前 `main` 与 `origin/main` 同步，开始工作时工作区干净。

### 1.2 已验证的问题

1. **首屏表达不完整**：Hero 中心圆为空，没有 `<h1>`、个人定位、价值说明或下一步入口；视觉装置强，但访客无法快速理解网站是谁、提供什么。
2. **移动端导航缺失**：导航链接在小于 `lg` 的视口直接隐藏，移动用户只能滚动，无法快速抵达博客、游戏、音乐、图片、收藏。
3. **Hero 响应式风险**：轨道容器固定为 800×800，三层半径最大 365px，窄屏主要依靠页面裁切，容易造成信息和图标不可见。
4. **未上线板块表达含混**：音乐、图片、收藏只有说明文字，没有内容、状态或后续方向；站点目标与页面完成度之间存在落差。
5. **跑马灯无障碍不足**：博客为连续动画并复制可交互链接；键盘和屏幕阅读器可能遍历重复内容，`prefers-reduced-motion` 下仍保持无限动画。
6. **构建依赖外部字体网络**：`next/font/google` 在构建时需要访问 Google Fonts；受限网络下已实际导致构建失败，降低可重复构建能力。
7. **SEO 覆盖不完整**：`/game` 未加入 sitemap；游戏页缺少 canonical 与独立 Open Graph 信息。
8. **统计只覆盖首次挂载**：`AnalyticsBridge` 的 `page_view` 只在根布局首次加载时触发，App Router 客户端路由切换不能稳定记录。
9. **工程门禁不完整**：没有独立 `lint`、`typecheck`、`test` 命令；现有 `verify` 不能覆盖静态代码质量和行为测试。
10. **依赖存在已知漏洞**：`npm audit` 显示 Next.js 16.2.2 关联 1 个 high、1 个 moderate 风险汇总；官方审计给出的非主版本修复目标为 16.2.10。
11. **资源利用不一致**：博客数据声明了封面资源但卡片未使用；其中个别图片体积超过 1MB。游戏图片 `sizes` 声明与三列布局不匹配，可能下载过大的响应式图片。
12. **文档状态滞后**：路线图仍标记 95%，但“上线动作”与统计平台接入尚未验证；README 过于精简，缺少本地验证和维护入口。

### 1.3 基线结果

| 检查项 | 结果 | 说明 |
|---|---|---|
| 本地开发页 | 通过 | `localhost:3100` 返回 200，标题为 `Vcrunyue Portfolio` |
| 内容检查 | 通过 | 当前内容字段、分类、日期和精选游戏顺序有效 |
| 资源检查 | 通过 | 14 个被内容层引用的本地资源存在 |
| 结构检查 | 通过 | Server/Client 边界和共享组件约束有效 |

## 2. 产品目标、用户场景、范围与非范围

### 2.1 产品目标

本轮把网站从“可浏览的个人内容集合”提升为“表达清楚、移动端完整、可持续维护、可重复构建并可安全发布的个人数字主页”。核心目标如下：

- 访客在 5 秒内理解站主身份方向、站点内容和可执行的下一步。
- 桌面端与移动端都能访问全部主要板块与游戏归档。
- 动效保留个性，同时满足键盘、屏幕阅读器和减少动态效果用户的基本需求。
- 未上线内容保持真实：明确“策展中”和主题方向，不伪造音乐、图片、影视或网站收藏。
- 每次提交都能通过 lint、JavaScript 类型检查、行为测试、内容/资源/结构检查和生产构建。
- 构建不依赖 Google Fonts 在线请求，已知高危直接依赖得到修复。
- 搜索引擎、统计平台和后续内容扩展拥有清晰接口。

### 2.2 目标用户与场景

1. **首次访问者**：从社交链接或搜索进入首页，快速理解站点主题并查看博客或游戏内容。
2. **移动端访问者**：单手浏览，使用固定导航跳转板块，阅读卡片并进入 `/game`。
3. **回访者**：直接定位博客、游戏或待上线收藏方向，获得稳定的导航和页面结构。
4. **站主本人**：只修改内容模块即可更新站点，运行一个 `verify` 命令即可完成发布前验证。
5. **搜索引擎与统计平台**：发现首页和游戏页，获得独立 metadata，并接收准确的页面访问与链接点击事件。

### 2.3 本轮范围

- 首页信息架构、Hero、固定导航、响应式布局和动效无障碍。
- 音乐、图片、收藏三个板块的“策展中”内容模型与诚实状态展示。
- 博客跑马灯的重复交互、减少动态效果和资源展示优化。
- 游戏卡片响应式图片配置、归档页 metadata 与站点地图。
- App Router 路由级页面统计。
- 本地字体方案、Next.js 安全补丁、ESLint、checkJs 类型检查、Node 测试与统一验证命令。
- README、维护/部署文档和路线图状态同步。
- 本地验证、Git 提交/推送与 Vercel 部署验证。

### 2.4 非范围

- 不虚构具体音乐、壁纸、影视、网站收藏或个人经历。
- 不新增 CMS、数据库、后台管理、登录、评论、搜索、支付或邮件订阅。
- 不把当前 JavaScript 项目整体迁移为 TypeScript；本轮使用 `checkJs` 提升类型可靠性。
- 不全面重做现有橙色/灰蓝视觉、轨道 Hero、博客跑马灯和游戏卡片语言。
- 不引入大型 UI 组件库或与现有规模不匹配的状态管理方案。
- 不承诺第三方统计后台已有数据；只完成代码接入能力与生产侧可验证步骤。

## 3. 页面、功能清单与核心交互流程

### 3.1 首页 `/`

#### 固定导航

- 第一层包含站点名、社交链接；第二层或可横向滚动区域在移动端显示全部板块链接。
- 桌面端维持当前单行布局，移动端不使用 JavaScript 菜单，避免新增 Client Component。
- 所有锚点板块设置合适的 `scroll-margin-top`，避免标题被固定导航遮挡。
- 当前交互继续使用 `data-track` 上报链接点击。

#### Hero

- 中心区域展示站点名、简短定位、说明文字和两个行动入口：“查看博客”“浏览游戏”。
- 保留三层轨道和六个兴趣图标，但尺寸通过 CSS `clamp()` 与自定义属性响应视口。
- 主标题使用唯一 `<h1>`；轨道和装饰图标对辅助技术隐藏，文本信息不依赖动画表达。
- 减少动态效果时停止轨道、自转、边框和跳动动画。

#### 博客

- 保留三行按分类分组的跑马灯。
- 连续滚动所需的第二份卡片标记为辅助技术隐藏，并从 Tab 顺序移除。
- 减少动态效果时停止滚动，只展示一份内容并允许水平浏览。
- 卡片使用已有封面作为轻量背景/视觉层，通过 Next Image 或 CSS 渐变控制可读性；优先避免直接加载未优化的 1MB 级图片。

#### 游戏

- 首页继续只展示九个精选游戏，顺序由 `featuredOrder` 控制。
- 卡片图片 `sizes` 与 1/2/3 列布局一致；缺图项继续使用设计过的渐变色，不伪造封面。
- “游戏”标题和新增的明确入口都可进入 `/game`。

#### 音乐、图片、收藏

- 三个板块从页面内硬编码文案迁移到内容层的 `upcomingSections`。
- 每个板块展示状态标签、简介和计划主题，例如“歌单与单曲”“壁纸与头像”“影视与工具网站”；这些是策展方向，不是虚构条目。
- 保留稳定锚点，未来只需替换内容数组或接入专用 renderer，不改变导航契约。

#### 联系与页脚

- 联系区继续使用站点 tagline，并提供可识别的社交/邮件入口。
- 页脚保持精简，确保 Gmail 链接语义和新窗口行为合理。

### 3.2 游戏归档 `/game`

- 保留完整游戏网格和返回首页入口。
- 增加 canonical、Open Graph 标题/描述与清晰 `<h1>`。
- 加入 sitemap，优先级低于首页。
- 响应式图片配置与首页一致，确保移动端和三列桌面端选择合理资源。

### 3.3 核心交互流程

```text
首次进入首页
  → 读取 Hero 定位
  → 选择“查看博客”滚动到 #blog，或“浏览游戏”进入 /game
  → 使用固定导航在各板块间跳转
  → 点击外部内容/社交链接并记录 link_click

进入 /game
  → 记录新的 page_view
  → 浏览完整游戏网格
  → 点击“返回首页”回到 /#game
```

## 4. 数据模型与接口变化

### 4.1 站点 Hero 配置

在内容层增加 `HeroContent`，由 Hero 组件消费：

```js
{
  eyebrow: string,
  title: string,
  summary: string,
  primaryAction: { label: string, href: string, track: string },
  secondaryAction: { label: string, href: string, track: string }
}
```

约束：站内锚点或路由必须存在；主标题不重复站点 metadata 的长描述；所有文案均来自内容层。

### 4.2 待上线板块配置

新增 `UpcomingSection`：

```js
{
  id: "music" | "images" | "favorites",
  title: string,
  statusLabel: string,
  intro: string,
  topics: string[]
}
```

约束：`id` 与导航锚点一一对应；`topics` 至少一项且不得是空占位符；当前只表达整理方向。

### 4.3 聚合出口

`siteContent` 扩展为：

```js
{
  site,
  hero,
  socialLinks,
  navLinks,
  sections: {
    blog,
    game,
    upcoming
  },
  progress
}
```

公开数据仍只从 `siteContent` 进入页面。内容校验、资源校验和结构校验同步认识新增字段，防止页面与模型漂移。

### 4.4 工程命令接口

`package.json` 增加并固定以下命令：

- `npm run lint`：ESLint CLI + `eslint-config-next/core-web-vitals`。
- `npm run typecheck`：`tsc --noEmit`，对现有 JavaScript 启用 `allowJs + checkJs`。
- `npm run test`：Node 内建测试，覆盖内容聚合、精选排序、进度计算和 sitemap。
- `npm run verify`：按 `lint → typecheck → test → check:* → build` 执行。

## 5. 技术架构与实现策略

### 5.1 组件边界

- `app/page.js`、Hero、Navbar、博客、游戏和待上线板块保持 Server Component。
- 直接 Client Component 仍只保留 `AnalyticsBridge` 和 `RevealSection`。
- Hero 的响应式行为使用 CSS，不使用 `window`、React 状态或媒体查询 Hook。
- 待上线板块继续复用 `SectionShell`，不恢复已删除的三个空壳组件。

### 5.2 字体与构建

- 移除构建期 `next/font/google` 网络请求。
- 使用随 npm 锁文件安装并由构建器打包的本地字体资源：Inter Variable 与 Outfit Variable；中文回退到系统中文字体栈。
- 保留 `--font-inter`、`--font-outfit` 语义变量，减少 CSS 改动；`--font-noto-sans-sc` 改为系统回退契约。
- 升级 Next.js 到 `npm audit` 建议的 16.2.10，并重新审计；不使用 `npm audit fix --force`。

### 5.3 样式与无障碍

- 将 Hero 大量内联几何样式收敛到语义类和 CSS 自定义属性，断点只控制规模与密度。
- 增加 skip link、唯一 H1、清晰 focus-visible、合适的导航 aria-label。
- 所有装饰 SVG/emoji 轨道使用 `aria-hidden="true"`。
- `prefers-reduced-motion` 下停止非必要动画，不以“减慢但无限播放”代替停止。
- 博客复制列表不重复暴露链接语义，鼠标悬停与键盘聚焦继续暂停普通动画。

### 5.4 SEO 与统计数据流

- metadata 继续从 `siteContent.site` 派生；游戏页补独立 canonical 与社交分享信息。
- sitemap 返回首页和 `/game` 两条记录。
- `AnalyticsBridge` 监听 App Router pathname；每个路径变化发送一次 `page_view`。
- `link_click` 继续事件委托，payload 仅包含 track、href 和截断文本，不加入个人敏感信息。

### 5.5 验证架构

- ESLint 负责 React、Hooks、Next.js 与基础无障碍规则。
- TypeScript `checkJs` 验证 JSDoc 数据模型、组件参数和函数返回值，不要求立即迁移文件扩展名。
- Node tests 验证纯函数和关键输出；现有三个脚本继续作为领域规则门禁。
- `next build` 是最终框架集成、静态生成与路由产物验证。
- Playwright CLI 用于桌面/移动真实浏览器冒烟，不在本轮引入持久化 E2E 测试框架。

## 6. 后续扩展方案

1. **真实内容接入**：站主准备好数据后，为 `music`、`images`、`favorites` 分别新增独立内容模块和 renderer；`upcoming` 状态可逐项下线。
2. **内容来源升级**：内容量明显增长后，再评估 MDX 或轻量 headless CMS；当前数组规模无需数据库。
3. **博客内页**：如果不再只链接外部资料，可增加 `/blog/[slug]`、文章 schema、RSS 与分页。
4. **图片管线**：新增图片时通过脚本验证尺寸、格式和体积，必要时增加自动 WebP/AVIF 转换。
5. **统计完善**：生产环境选择一种统计平台作为主实现，补充部署环境变量、事件命名表与数据保留说明。
6. **自动化发布**：后续可增加 GitHub Actions，在 push 前运行 `npm ci && npm run verify`，由 Vercel 只部署已通过的提交。

## 7. 分阶段路线图与推荐实施顺序

### 阶段 A：安全与工程门禁

1. 升级 Next.js 安全补丁并复查 audit。
2. 替换在线字体构建依赖。
3. 增加 ESLint、checkJs、Node tests 和统一 `verify`。
4. 修复新门禁发现的现有问题。

**阶段验收**：`lint`、`typecheck`、`test`、三个 `check:*`、离线条件下 `build` 全部通过，audit 无 high/critical。

### 阶段 B：首屏、导航与全局无障碍

1. 扩展 Hero 内容模型并重构响应式 Hero。
2. 实现移动端可见导航、skip link 和锚点偏移。
3. 修正减少动态效果策略和基础焦点体验。

**阶段验收**：桌面 1440px、移动 390px 下 Hero 无横向溢出；所有板块可通过键盘与导航抵达；页面只有一个明确 H1。

### 阶段 C：内容体验、SEO 与统计

1. 增加 `upcomingSections` 并渲染诚实状态卡。
2. 修复博客复制链接语义、减少动态效果和封面利用方式。
3. 优化游戏响应式图片，补 `/game` metadata 和 sitemap。
4. 让 page_view 覆盖客户端路由变化。

**阶段验收**：首页各导航锚点均有实质状态；博客无重复 Tab 项；sitemap 包含两条页面 URL；路由跳转触发页面事件调用。

### 阶段 D：全链路验收、文档与发布

1. 更新 README、维护、部署和路线图文档。
2. 运行完整 `npm run verify` 与 `npm audit`。
3. 启动本地服务，用真实浏览器检查首页、所有锚点和 `/game` 的桌面/移动核心流程。
4. 检查工作区差异，提交并推送 `main`。
5. 触发/检查 Vercel 部署，验证生产首页、`/game`、`robots.txt`、`sitemap.xml`。

**阶段验收**：本地全绿；浏览器无阻断错误；GitHub 远程包含提交；Vercel 生产或预览部署成功且核心 URL 返回 200。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| checkJs 一次暴露较多旧类型问题 | 阶段 A 工作量上升 | 逐个补 JSDoc/默认值，不通过关闭规则掩盖问题 |
| 字体替换造成字宽变化 | 导航或卡片换行变化 | 使用变量字体并做 390/768/1440 三档视觉检查 |
| Hero 动效重构改变现有视觉 | 品牌识别度下降 | 保留三层轨道、六个主题与橙色中心，只重排信息和尺度 |
| 博客封面体积过大 | LCP/带宽退化 | 只通过 Next Image 优化或低透明度按需加载；必要时压缩超大资源 |
| 第三方统计对象不存在 | 事件无落点 | `trackEvent` 保持安全空操作，生产文档明确接入与验证步骤 |
| Vercel 未授权或项目未关联 | 无法完成部署检查 | 使用现有 Vercel 项目连接；若外部授权缺失，保留本地与 GitHub 已验证结果并明确外部阻塞 |
| 安全补丁引入行为变化 | 构建或运行回归 | 仅同一 minor 的 audit 建议版本，升级后执行全量门禁与浏览器回归 |

## 9. 总体验收标准

### 产品与交互

- 首屏包含明确 H1、定位、说明和两个可用入口。
- 390px 移动端可以看到并使用全部主导航，不出现页面横向滚动条。
- 首页博客、游戏、音乐、图片、收藏、联系均有可识别的内容或真实状态。
- `/game` 可进入、可返回、完整展示游戏清单。
- 键盘用户可看到焦点并完成主流程；减少动态效果时非必要动画停止。

### 数据与架构

- 页面不直接散落可配置 Hero/待上线板块文案。
- 新增内容模型有 JSDoc 类型、聚合出口和验证规则。
- Server/Client Component 边界符合仓库约定，没有无必要的客户端组件。
- 不存在虚构的个人音乐、图片、影视或网站条目。

### 工程质量

- `npm run lint`、`npm run typecheck`、`npm run test` 全部通过。
- `npm run check:content`、`check:assets`、`check:structure` 全部通过。
- `npm run build` 在不访问 Google Fonts 的情况下通过。
- `npm audit` 不含 high 或 critical 风险。
- `npm run verify` 一次完成全部提交前门禁。

### SEO、监控与发布

- 首页和 `/game` 均有唯一标题、描述与 canonical。
- `sitemap.xml` 同时包含首页与 `/game`，`robots.txt` 指向 sitemap。
- 首页与 `/game` 路由变化可触发 `page_view`，带 `data-track` 的链接触发 `link_click`。
- 提交已推送到 GitHub，Vercel 部署完成；生产核心 URL 返回 200。
